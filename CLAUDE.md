# Radmin Grid - заметки для Claude

Portable-оболочка для Radmin Viewer 3 (WinForms, .NET Framework 4.x). Что делает программа - в README.md,
история изменений - в CHANGELOG.md. Интерфейс, журнал и сообщения - на русском. Общение с владельцем - на русском.

## Сборка

- `build.bat` - штатный `csc.exe` из .NET Framework 4.x, без Visual Studio и SDK. Собирает `src\*.cs` в один `RadminGrid.exe`.
- **Компилятор понимает только C# 5.** Нельзя: `$"..."`, `?.`, `nameof`, члены через `=>` (`int X => 1;`),
  `out var`, кортежи, `using static`, инициализаторы автосвойств. Лямбды, LINQ и `delegate { }` можно.
  После правок всегда собирать и проверять, что нет ошибок.
- Новые сборки .NET подключаются через `/r:` в `build.bat`. Если нужен ещё один файл `.cs`, достаточно положить его в `src\`.
- Исходники - UTF-8 (с BOM или без, сборка идёт с `/codepage:65001`), концы строк LF. `build.bat` - CRLF (см. `.gitattributes`).
- Сообщения в `build.bat` - **на английском**: консоль cmd в OEM-кодировке и портит кириллицу.
- Прав администратора нет и не должно быть нужно ни для сборки, ни для работы (`asInvoker` в `src\app.manifest`,
  ничего не писать в HKLM и Program Files).

## Версии и релизы

- Версия задаётся **только** в `src\AssemblyInfo.cs` (`AssemblyVersion`/`AssemblyFileVersion`/`AssemblyInformationalVersion`).
  В `src\app.manifest` в `assemblyIdentity` та же версия - менять вместе.
- Выпуск: поднять версию → раздел `## [X.Y.Z] - дата` в CHANGELOG.md (он становится описанием релиза) →
  коммит → `git tag vX.Y.Z` → `git push origin main vX.Y.Z`. Дальше `.github/workflows/release.yml` проверит, что тег совпадает с версией,
  соберёт exe, посчитает `SHA256SUMS.txt` и опубликует релиз. Тег с дефисом (`v0.2.0-beta`) - предварительная версия.
- Релиз нельзя перевыпустить под тем же тегом: установленные копии сравнивают версии. Ошибся - выпускай следующую версию.
- `.github/workflows/build.yml` собирает каждый push в main.

## Обновления (src/Updater.cs, src/UpdateDialog.cs)

- Репозиторий `barnibeats/RadminGrid` **публичный**. Обновления идут через GitHub Releases API без токена и без авторизации.
- В интерфейсе программы репозиторий, ссылки на него и слово GitHub показывать нельзя: пользователь не должен видеть, откуда приходят обновления.
- Проверка обновления: SHA-256 из поля `digest` ассета или `SHA256SUMS.txt`, имя сборки `RadminGrid`, версия файла = версия тега.
  Без контрольной суммы не устанавливать.
- Установка - при закрытии программы: работающий exe → `RadminGrid.exe.old`, `.new` → на его место, запуск с `/updated:<PID>`.
  Новая копия ждёт выхода старой (мьютекс «один экземпляр на папку» в `Program.cs`) и удаляет `.old`.
- Имя ассета - строго `RadminGrid.exe`: по нему `Updater` ищет файл в релизе.

## Подводные камни в коде

- Иконки - символы шрифта Segoe MDL2 из частной области Unicode (`Theme.Ico*`, строки вида `"\uE..."`).
  В редакторе и выводе инструментов они **невидимы** и выглядят как `""`. При правке строк с иконками
  не перепечатывать их вручную - использовать константы `Theme.Ico*` или менять строку точечно.
- UI рисуется своими контролами (`RButton`, `Toggle`, `Choice`, `Card` в `Theme.cs`), цвета - только из `Theme.*`:
  тема переключается на лету (`MainForm.ReapplyTheme` пересоздаёт интерфейс). Новые окна оформлять через `Theme.StyleForm`.
- Фоновую работу делать через `ThreadPool` и возвращаться в UI через `BeginInvoke` (см. `MainForm.CheckUpdates`).
- Журнал - `MainForm.AppendLog`; он же пишет `RadminGrid.settings.log`.
- Автоматизация Radmin - через UI Automation и WinAPI (`RadminController.cs`, `Native.cs`). Номер смены читается OCR Windows
  из снимка окна (`ShiftOcr.cs`) - на удалённый ПК не уходит ни кликов, ни клавиш, так и должно остаться.
- `test\FakeRadmin.cs` - эмулятор Radmin Viewer для проверки без серверов (логин `admin`, пароль `test123`).

## Нельзя коммитить

`RadminGrid.settings.xml` (логин, пароль в base64, адреса узлов), `*.log`, `*.rpb`, `*.exe`.
Перед коммитом проверять `git status` - всё это уже в `.gitignore`, но папка проекта рабочая и эти файлы в ней лежат.

## Окружение

- Windows 10/11. Для работы с GitHub нужен `gh` под аккаунтом `barnibeats` (`gh auth login`).
- Коммиты - от `barnibeats` с noreply-адресом GitHub, не с личной почтой.
